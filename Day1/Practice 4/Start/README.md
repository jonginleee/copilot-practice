# Copilot 실습: Todo 앱 만들기

## 실습 목표

GitHub Copilot을 활용하여 Python 로직 → 테스트 → API → UI까지 간단한 서비스 개발 흐름을 한 번에 경험

---

## 사용 기술

* Python: 핵심 비즈니스 로직 구현
* pytest: 핵심 로직 단위 테스트
* FastAPI: REST API 구성
* Streamlit: API 기반 UI 구현

---

## 구현 범위 (Minimal Spec)

기능 4개만 구현

* 할 일 추가
* 목록 조회
* 완료 토글
* 삭제

조건

* DB 없이 메모리 기반
* API 4개만 구성 

---

## 진행 순서

1. Python으로 TodoService 구현
2. pytest로 핵심 로직 테스트 작성
3. FastAPI로 로직을 API에 연결
4. Streamlit으로 API 호출 UI 구성

각 단계는 구현 후 바로 검증하고, 통과하면 다음 단계로 넘어가는 방식으로 진행

---

## 권장 진행 방식

한 번에 끝까지 만들지 말고 아래 순서대로 진행

1. 기능 1개 또는 작은 단위 구현
2. 바로 실행 또는 테스트로 확인
3. 이상 없으면 다음 기능 추가
4. 마지막에 API와 UI까지 연결 검증

이 실습의 핵심은 "구현 → 즉시 검증 → 다음 단계 진행" 흐름을 반복하는 것

---

## 단계별 실습 및 검증

### 1단계. Python TodoService 구현

목표

* 메모리 기반으로 할 일을 저장하는 서비스 클래스 구현
* 최소 기능 4개 제공
	* 할 일 추가
	* 목록 조회
	* 완료 토글
	* 삭제

이 단계에서 확인할 것

* 서비스가 API 없이 단독으로 동작하는가
* 메서드 이름과 반환 형태가 스스로 설명 가능할 정도로 단순한가
* 데이터 구조가 이후 FastAPI에서 그대로 쓰기 쉬운가

검증 방법

* Python 파일에서 서비스 객체를 직접 생성해 메서드를 순서대로 호출
* add 후 list 결과에 항목이 보이는지 확인
* toggle 후 완료 상태가 바뀌는지 확인
* delete 후 목록에서 제거되는지 확인

다음 단계로 넘어가는 기준

* 예외 없이 기본 CRUD 흐름이 동작
* 같은 동작을 2번 반복해도 상태 관리가 일관됨

---

### 2단계. pytest로 핵심 로직 테스트 작성

목표

* 서비스 로직을 테스트로 고정
* 이후 API와 UI를 붙여도 핵심 기능이 깨지지 않도록 안전망 확보

우선 작성할 테스트

* 할 일 추가 시 목록에 포함되는지
* 목록 조회 시 현재 데이터가 반환되는지
* 완료 토글 시 상태가 바뀌는지
* 삭제 시 데이터가 제거되는지

가능하면 추가할 테스트

* 존재하지 않는 ID 토글 또는 삭제 시 처리 방식
* 빈 제목 입력 시 허용 여부

검증 방법

* 프로젝트 루트에서 pytest 실행
* 실패한 테스트가 있으면 서비스 코드를 수정한 뒤 다시 pytest 실행

권장 검증 명령

```bash
pytest
```

다음 단계로 넘어가는 기준

* 핵심 로직 테스트가 모두 통과
* 서비스 수동 확인 없이도 테스트만으로 동작 신뢰 가능

---

### 3단계. FastAPI로 로직 연결

목표

* TodoService 기능을 HTTP API로 노출
* UI가 붙기 전에 API 단독 사용이 가능하도록 구성

구성 권장

* POST: 할 일 추가
* GET: 목록 조회
* PATCH 또는 PUT: 완료 토글
* DELETE: 할 일 삭제

이 단계에서 확인할 것

* 라우트가 서비스 메서드와 1:1로 자연스럽게 연결되는가
* 요청/응답 구조가 UI에서 사용하기 쉬운가
* 에러 응답이 최소한 일관되게 처리되는가

검증 방법

* FastAPI 서버 실행
* /docs에서 4개 API를 순서대로 호출
* 추가 → 조회 → 토글 → 삭제 흐름이 브라우저에서 재현되는지 확인

권장 검증 명령 예시

```bash
uvicorn src.todo_app.main:app --reload
```

다음 단계로 넘어가는 기준

* /docs에서 모든 엔드포인트 호출 가능
* Swagger UI 기준으로 CRUD 흐름이 정상 동작
* API 응답만 봐도 현재 상태를 확인할 수 있음

---

### 4단계. Streamlit UI 연결

목표

* FastAPI를 호출하는 간단한 화면 구성
* 사용자가 브라우저에서 CRUD 흐름을 직접 조작 가능하도록 구현

최소 UI 구성 예시

* 새 할 일 입력창
* 목록 표시 영역
* 완료 토글 버튼
* 삭제 버튼

이 단계에서 확인할 것

* UI가 직접 데이터를 들고 있지 않고 API 결과를 기준으로 동작하는가
* 버튼 클릭 후 목록이 즉시 갱신되는가
* 예외 상황에서 최소한의 안내 메시지가 보이는가

검증 방법

* Streamlit 실행
* 브라우저에서 직접 항목 추가, 토글, 삭제 수행
* UI 변경이 실제 API 상태와 일치하는지 확인

다음 단계로 넘어가는 기준

* 브라우저에서 전체 CRUD 시나리오를 끝까지 수행 가능
* 새로고침 이후에도 현재 API 상태 기준으로 화면이 다시 그려짐
